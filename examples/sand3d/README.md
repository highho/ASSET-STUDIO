# sand3d 示例程序

几段可以直接真跑的 sand3d 程序，用来验「代码 → 模型」这条链路。

## 怎么跑

1. 打开 http://127.0.0.1:8080/studio （资产库页头的「用代码新建」也到这儿）
2. 点「板件模板 / 人偶模板」直接载入，或把下面任一 `.py` 的内容整段粘进左侧编辑器
3. 点「运行 ⌃↵」——程序交给本机 Blender 里的 bpy 真跑，导出的 GLB 直接进右视口
4. 满意了填个资产名，点「存为新资产」

或者走接口：

```powershell
$code = @{ code = (Get-Content -Raw examples/sand3d/plate-cbore.py) } | ConvertTo-Json
Invoke-WebRequest -Uri http://127.0.0.1:8080/api/sand3d/run -Method Post -Body $code -ContentType application/json -OutFile plate.glb
```

## 两段的实测（Blender 运行时，本机 UPBGE 5.0.1 + sand3d 1.6.3）

| 程序 | 结果 |
| --- | --- |
| `plate-cbore.py` | 1 个零件 · **360 面 / 477 顶点** · mm · 1.5 s · 29,076 B |
| `lamp-fixture.py` | 4 个零件 · **474 面 / 669 顶点** · mm · 1.5 s |
| `humanoid.py` | 18 个零件（头/颈/躯干/胯 + 左右肩头/上臂/前臂/手 + 左右小腿/大腿/脚）· **10,978 面 / 11,234 顶点** · 1.6 s |

两个程序用的都是 sand3d 的基础动词：`box` / `cylinder` / `sphere` / `fillet` / `hole`（`cbore` 沉孔）/ `grid`（孔位）/ `at`（摆放，含 `ry` 转角与 `anchor`）/ `material` / `group` / `export`。

## 参数化人偶：人物模型不能「反推」，但能「用参数造」

`humanoid.py` 是 `/studio` 里的「人偶模板」。它把人体拆成 16 个可动的零件，用五个数控制比例和姿态：

```python
H = 1700        # 身高
SHOULDER = 430  # 肩宽
THICK = 1.0     # 四肢粗细系数（0.8 细、1.2 壮）
SPREAD = 18     # 手臂外张角（A 字站姿 15～25）
STANCE = 100    # 两脚间距
HEAD = 7.2      # 头身比：身高 / HEAD
```

实测：默认参数整体包围盒 **0.8 m 宽 × 1.8 m 高**；改成 `THICK=0.6 / STANCE=220 / SPREAD=40` 之后变成 **1.1 m × 1.8 m** —— 身高不变、更瘦、站得更开，说明这几个数真的在驱动几何，而不是装饰。

这条路的边界：它长出的是「可改比例的人形」，不是「像某个人」。要某个具体人物的外观，只能保留原始网格文件，拿代码重造不出来。

## 反过来的方向（模型 → 代码）不在这两个文件里

检视台「代码」页签会把当前资产的模型反推成 `s3d.box` 程序，但那是**近似**：

- 多零件、以方料为主的资产（例如「检视台支架」，6 个网格）→ 6 个盒子的程序能看懂，也能量出大致尺度；
- 单个网格的曲面资产（例如「黄铜环形结」，1 个网格 19,200 面）→ 只剩一个包围盒，**形状完全丢失**。这种情况代码页签会明确警告，别拿它当重建依据。

要精确重建曲面件，只能从这边重新写程序（用 `cylinder` / `revolve` / `sweep` / `loft` 这类动词），没有「一键逆向」。
